# class-based-environment-project-of-Memory-16-x-32-
This verification project delivers a class-based SystemVerilog environment architected to validate a 16×32 memory module. The methodology is fully modular and transaction-driven, leveraging parallel class execution and deterministic synchronization to maintain pipeline integrity.
Stimulus is generated in the sequencer and transferred to the driver through a mailbox channel, with **two synchronization events** coordinating both sides to ensure proper pacing and eliminate command overruns. The driver executes on a **non-blocking model at the rising clock edge**, enabling uninterrupted stimulus flow. In contrast, the monitor operates **blocking at the same edge**, guaranteeing coherent sampling of DUT behavior.
All components run concurrently, with their operational tasks launched using **fork–join_any**, enabling true parallelism across sequencer, driver, monitor, scoreboard, and coverage collector.
Event-based synchronization governs cross-class communication. Each class triggers defined events while others wait on them, creating a controlled transaction handoff model that prevents timing hazards and ensures deterministic progression.
Transactions captured by the monitor are routed to the scoreboard and coverage collector, enabling rigorous checking of data integrity and closure of functional coverage objectives. Mailboxes serve as thread-safe conduits for all transaction movement across the environment, decoupling class execution and upholding clean transaction-level modeling practices.
Overall, the environment validates memory read/write ordering, reset handling, data consistency, and protocol conformance while demonstrating scalable class-based verification infrastructure.
